# Tests

Run all cases with `python3 tests/run.py`, or a subset with `python3 tests/run.py <name-fragment>...`. `-j N` runs N cases at a time (default 4; `-j 1` runs them one after another); results print in case order whatever the completion order, and each case compiles to its own path under `build/tests/`.

Each case in `tests/cases/` is a SIGNAL source `name.sig` with one of:

- `name.out` — the expected output trace. The compiled program runs its steps indefinitely and prints one line per step: the values of the model's outputs in interface order, separated by one space, with `-` for an absent output. An array output prints as its elements in row-major order, separated by one space, and as one `-` when absent. Unsigned types and `pointer` print as unsigned decimal. A program whose model has no outputs prints no step lines; its output is whatever its effects write. The harness reads as many lines as the file has, then stops the program.
- `name.err` — a fragment the compiler's error output must contain; the compiler must reject the program.

A trace case may also have `name.in`, a regular file the harness opens as the program's standard input (fd 0) and feeds as is; it may be binary, for a program that reads or maps fd 0 through its own effects. When a program's clocks form more than one tree (D8), or its model has input signals, each step reads one line: `k` characters, `1` for a present root clock and `0` for an absent one, then, for each input in interface order whose root is present and whose type is not `event`, one space and its value; an array input gives its elements in row-major order, each after one space. Roots are ordered by their earliest-declared signal, interface signals before locals. A value is an optional `-` and 1 to 20 decimal digits whose magnitude is below 2^64, stored in the input's type with wrapping (D4); a `boolean` value is `0` or `1`, an enumerated value is its ordinal. End of input at the start of a line ends the program with exit status 0. Any other line, including one without its trailing newline, ends it with status 2 and `presence input malformed at step N` on standard error.

A trace case may also have `name.exit`: its first line is the exit status the program must end with, and the rest is a fragment its standard error must contain. The harness then runs the program to exit and compares every line of output with `name.out`.

The compiler is run with an empty PATH, so it can invoke no external tool.

`python3 tests/run.py --compiler PATH [<name-fragment>...]` runs the same cases with the native compiler executable at PATH in place of `python3 bootstrap/sigc.py`, with the same empty PATH and timeouts.

`tests/cases/m4/` holds the cases for the extensions the self-hosted compiler (M4, D13) needs: `argc` (the runtime keeps argc in `x25` and argv in `x26`; the case has no arguments, so it prints 1), `load` and `store` inside `iterate` (`load_*`, `store_*`, `syscall_iterate`), the run-time count `X := 0 .. E` (`range_*`), and string constants (`string_*`).

`tests/cases/m5/` holds the bare-metal cases (M5, D15): programs whose top model carries an `Interrupt` or `Boot` pragma, compiled to an ELF for QEMU `virt`. A trace case runs as `qemu-system-aarch64 -M virt -cpu cortex-a72 -nographic -kernel EXE` with standard input `/dev/null`; its trace is what the program writes to the PL011 UART, one line per step in the format above, starting with the `Boot` step's line, and the harness stops QEMU after the expected lines with the same 5 s timeout (`timer.sig`'s 11 lines take about 0.16 s). `bootstrap/sigc.py` has no pragmas (D13), so `run.py` skips `m5/` unless `--compiler` is given, and `diff.py` skips `m5/` in both modes; `selfhost.py` runs them through `run.py --compiler build/m4/stage2`.

`tests/cases/m6/` holds the Cortex-M cases (M6, D16): programs whose top model carries the pragma `Machine "mps2-an385"`, compiled to an ELF32 for QEMU `mps2-an385`. A trace case runs as `qemu-system-arm -M mps2-an385 -cpu cortex-m3 -nographic -no-reboot -kernel EXE` with standard input `/dev/null`; its trace is what the program writes to UART0, in the format above, starting with the `Boot` step's line. `run.py` takes the QEMU command for a suite from its `QEMU_COMMANDS` table, so `run.py` without `--compiler`, and `diff.py` in both modes, skip `m6/` as they skip `m5/`.

`tests/cases/m11/` holds the cases for characters, strings and `read`/`write`/`writeString` (M11, D21): `char_*` and `string_*` for the types, constants, conversions, comparisons and the rejected uses, `read_*` for reading on macOS (`.in` and `.exit`; end of input exits 0, a malformed line exits 2) and its rejection on QEMU, and the exit programs `greet` (macOS) and `greet_virt`/`greet_mps2` (QEMU), whose `.out` holds the written lines and the step lines in stream order. They are stage-2 only, as `m5` to `m10` are.

`tests/cases/m12/` holds the cases for `real` (binary32) and `dreal` (binary64) (M12a): `literal`, `bounds`, `overflow_*`, `dot_*` and `constant_*` for literals converted at compile time (round half to even, digits past the 768th folded into one sticky digit, `-` flipping the sign bit, a literal that rounds to infinity rejected, constants other than a literal, `-literal` or a constant name rejected); `arithmetic`, `compare`, `convert`, `select` and `select_wide` for the operators, the IEEE comparisons (`=` and the orderings false on NaN, `/=` true), the conversions to and from integers and the widening of `real` to `dreal`; `widen_*` for a `real` stored as an element of a `dreal` array by `[...]`, `next`, a restructuration, a partial definition and an `iterate`; `literal_capacity` for the capacity error `REALS`; `input*`, `read_write` and `read_malformed` for reading on macOS (`.in` and `.exit`; input that does not match the grammar or overflows exits 2; `input_exponent_long` has an exponent above 100000 offset by 100002 zeros after the point); `implicit`, `narrowing`, `mixed_*`, `modulo`, `power_real` and `convert_boolean` for the rejected uses; `real_mps2`, `dreal_mps2` and `constant_mps2` for the rejection on `mps2-an385`; and `arithmetic_virt` and `literal_virt` on QEMU `virt`. A real prints as the shortest decimal that reads back to the same value, laid out as Python's `repr`: plain for a decimal exponent from -4 to 15, `.0` on an integral value, else `d.ddde+XX`; `nan`, `inf`, `-inf` and `-0.0`. They are stage-2 only, as `m5` to `m11` are.

`python3 tests/differential.py [--compiler PATH] [N]` checks that Cortex-M and macOS print the same trace (D16). For each seed it generates, with Python's `random` seeded by it, a program over the D4 integer types except `pointer` that uses every arithmetic, bitwise, shift, comparison and boolean operator, conversions, `if`, `when`/`default`, delays, a constant table, a gather and an `iterate`, with literals biased to type boundaries. The macOS variant reads its roots `START` and `TICK` from a generated `.in` (one `START` step, then 8 `TICK` steps); the MPS2 variant names `START` in `Boot` and `TICK` in `Interrupt {TICK} "15"` and programs SysTick in the boot step. Both are compiled with PATH (default `build/m4/stage2`) into `build/differential/SEED/`, and the 9-line traces must be equal. It checks every seed in `tests/differential_seeds.txt`, then N fresh seeds (default 200), printed first; a fresh seed whose traces differ, or whose MPS2 variant alone fails to compile, is appended to `tests/differential_seeds.txt`, to be reduced to a case in `tests/cases/m6/` whose `.out` is the macOS trace. It exits 1 when any seed fails. `-j N` checks N seeds at a time (default 4), printing results in seed order; `--seeds S,S,...` replaces the fresh random seeds with the given ones, for this method and for `m9b`, `m9c` and `m10a`, and a failing given seed is not appended to `tests/differential_seeds.txt`. The `m6/diff_*` cases cover what the generator does not produce (run-time `iterate` counts, negative and out-of-range indexes, array snapshots and copies, enumerations, mixed-width operands, mixed-size tables, 64-bit division edges); each is the MPS2 variant of a program whose macOS variant printed the same trace, and its `.out` is that trace.

`python3 tests/differential.py [--compiler PATH] m11 [N]` checks `char` and `string` (M11). For each of N fresh seeds (default 200) it generates a program over `START` and `TICK`, as above, with `char` signals from `char` of integers, `$`, `when`/`default`, `integer` of a char and char comparisons against a constant written as `'c'`, `'\xHH'` or `'\ooo'`; `string` signals selected by `if` among constants that share prefixes and differ in one byte, delayed, and compared with every comparison operator; and `write` and `writeString` of chars, strings, integers and booleans, ordered by `-->`. The macOS and MPS2 traces, write lines included, must both equal the trace an independent Python model gives. Each seed also feeds 16 steps of random input to one macOS program that reads two strings (0–255 bytes, never 0x0A, often a prefix of each other or one byte apart) and two chars (codes 0–255 except 10) with `read`, writes the first of each back and writes `<`, `=` and `<=` for each pair: the output must equal the input bytes and Python's `bytes` comparison. Programs go to `build/differential/m11/SEED/`. A failing seed is printed, not appended to `tests/differential_seeds.txt`, which holds seeds for the method above. `--seeds S,S,...` replaces the fresh seeds.

`python3 tests/differential.py [--compiler PATH] m12 [N]` checks `real` and `dreal` (M12a) on macOS against Python (`float.__repr__`, `float()`, `struct` and `fractions`); the macOS-versus-MPS2 comparison above does not cover reals, since `mps2-an385` rejects them. It compiles two programs into `build/differential/m12/`: one echoes a `real` and a `dreal` input, one computes every arithmetic operator, comparison and conversion of `real`, `dreal`, `long` and `ulong` inputs. For each of N fresh seeds (default 200) it feeds the echo program 24 steps of the shortest text of random bit patterns of every class (zeros, subnormals, normals, the largest finite, infinities, NaN), their exact decimal expansions, random decimal strings up to 800 digits and exact midpoints between adjacent values with and without a nonzero digit past the 768th, then one input that overflows, which must exit 2; the printed values must equal the oracle's. It feeds the arithmetic program 24 steps of random operands, with binary32 results rounded from the exact binary64 result, and compiles a program of 12 random literals into `build/differential/m12/SEED/`, drawn from the same texts as the echo inputs except `nan` and the infinities. Once per run it also compiles a `real` and a `dreal` literal with 1000002 zeros after the point and the exponent 1000001, which must print `0.01`. A failing seed is printed, not appended to `tests/differential_seeds.txt`, which holds seeds for the method above. `--seeds S,S,...` replaces the fresh seeds.

`python3 tests/dump.py PASS SOURCE` prints `sigc.py`'s table after pass PASS for SOURCE: per column, a line `COLUMN COUNT` and then one value per line. A compile error in the pass ends the output with `error LINE COLUMN MESSAGE`. The passes are `tokens` (columns `kinds`, `texts`, `lines`, `columns`) and `program`, the `Program` returned by `parse_program` (its `finish_model` rewrites included), whose `name` prints as a one-value column and whose nested `types` and `models` print as columns `types.kind` … `models.labels`. The pass `flat` is the `Program` returned by `instantiate` on that `Program`, printed with the same columns. The pass `rows` is the pair `lower` returns for the `flat` program, its `Rows` as columns `rows.op` … `rows.effects.param` and its `Loops` as columns `loops.index` … `loops.count`, followed by the `flat` program's `types.kind` … `types.size`, `table_types` and `table_values` columns as `lower` leaves them, with the array types and `indices` tables it adds. The pass `clocks` is the `Clocks` that `clock_calculus` returns for those rows, as columns `parent` … `roots`, except that `parent` prints each clock's representative, `find` of it, so the column does not depend on how far `find` has halved paths. The pass `schedule` is what `schedule` returns for those rows and clocks, as columns `order` and `loop_orders`, followed by the snapshots it records, `loops.snapshots` as `snapshots` and `rows.snapshotted` as `snapshotted`. The pass `code` is the `Code` that `emit_code` returns for that schedule, before `encode`: columns `form`, `op0` … `op3`, then each instruction's target as `target_section` and `target_offset`, the section (`0` text, `1` data) and byte offset of the label it refers to, or `-1` and `0` when it has none or the label is never placed; then the data items in the order `emit_code` adds them, as `data_offsets`, their byte offsets, and `data_alignments`, the alignment each was added with; then `data`, the data section with one byte per line as a decimal. A value prints as its decimal or its text, `None` as `none` and a boolean as `0` or `1`; a set prints as its items in ascending order; a tuple or list prints its items separated by one space, each nested tuple or list inside `[` `]`, so an empty one prints an empty line, or `[]` when nested. A compile error in any pass prints only the error line. A source that is not valid UTF-8 prints only `sigc: error: MESSAGE`, the line `sigc.py` writes to standard error.

`tests/diff.py` compiles every case in `tests/cases/` and prints one `DIFF` line per differing case, then `N cases, K differ`; it exits 1 when any case differs. A compiler argument is either a `.py` file, run with Python, or a native executable; compilers run with an empty PATH.

- `python3 tests/diff.py dump PASS COMPILER` compares `dump.py PASS SOURCE` with the file `COMPILER SOURCE -o OUT` writes. COMPILER is the SIGNAL compiler built with its `DUMP_PASS` constant set to the pass, which writes the dump to OUT instead of an executable. COMPILER may also be `compiler/sigc.sig`: diff.py then replaces its line `constant integer DUMP_PASS = 0;` with the pass number (`tokens` is 1, `program` is 2, `flat` is 3, `rows` is 4, `clocks` is 5, `schedule` is 6, `code` is 7) and builds it with `bootstrap/sigc.py` into `build/m4/` before comparing.
- `python3 tests/diff.py image OLD NEW` compiles every case with both compilers and compares exit statuses, standard output, standard error and executables byte for byte.

`python3 tests/selfhost.py` checks self-hosting (M4, D13). It builds `compiler/sigc.sig` three times into `build/m4/`: stage 1 with `bootstrap/sigc.py`, stage 2 with stage 1, stage 3 with stage 2. Stage 2 must equal stage 1, which is `sigc.py`'s executable for the compiler, and stage 3 must equal stage 2. It then runs `run.py --compiler build/m4/stage2` and `diff.py image bootstrap/sigc.py build/m4/stage2`, and exits 1 if any of these fails. It takes about 3.5 minutes.

No test invokes `as`, `ld`, `xcrun` or `codesign`. The executables are checked against `sigc.py`'s byte for byte, by `diff.py image` and `selfhost.py`, so the M3 oracles in the retired `tests/backend.py` are no longer needed (D12, D13). `sigc.py` is the frozen stage 0.

## Divergences of compiler/sigc.sig from bootstrap/sigc.py

- Capacities: every table in `compiler/sigc.sig` has a fixed capacity (the `*_CAP` constants written by `compiler/tables.py`). A program that exceeds one is rejected with `program exceeds compiler capacity: TABLE`, where `sigc.py` has no limit. Examples: 2^21 tokens including the end-of-file token, 16000 guards, 2^20 clocks (about 58,000 flat model calls), 2^24 dump items, and message text over 64 KiB.
- Iterate bound: each of the compiler's own `iterate` loops runs at most `PARSE_CAP` (2^28) times, so a program whose data-derived loop bound exceeds that is a capacity error (for example, 12,000 samplings with a 15-deep clock chain). The conversion of real literals budgets 80000 steps per literal, so a program with more than about 3350 real literals is rejected with `program exceeds compiler capacity: REALS` at 1:1.
- Effects: a program with more than 4096 effects is a capacity error, because the effect-order check keeps an `EFFECT_ORDER_CAP` × `EFFECT_ORDER_CAP` matrix.
- OS errors print `sigc: error: [Errno N] PATH`, without Python's `strerror` text or quotes.
- Staged output: the executable is written to `DIR/.NAME.` plus the process id as 8 lowercase hex digits, opened with `O_EXCL` without retry, then renamed over `DIR/NAME`. `sigc.py` uses a random `mkstemp` suffix.
- `unexpected character` and quoted tokens in parse messages show the raw bytes, not Python's `repr` escaping of `\`, quotes, control and non-printable characters (F4).
- Only the form `SOURCE -o OUTPUT` is accepted; any other argument list exits 2 with no usage text (F5).
- The source must be seekable: a pipe fails with `[Errno 29]` (F6).
- If standard output cannot be written, for example when it is closed and the presence line is printed, the exit status is 1, where `sigc.py` exits 0 (F7).
- Paths are read up to 4096 bytes: a longer source or output path fails with `[Errno 63]` and is printed truncated, and the errno for paths near `PATH_MAX` can differ from `sigc.py`'s (F8).
- A source over the `SRC` capacity reports its capacity error at 1:1.
- In a dump build (`DUMP_PASS` nonzero), a dump file that cannot be opened exits 1 without a message.
- If the 128 MiB output buffer cannot be mapped, the compiler exits 3 with `memory reservation failed`, as a failed array reservation does (D6); `sigc.py` has no such buffer.
- Pragmas (M5, D15): `pragmas … end pragmas` on the top model selects the QEMU `virt` target and an ELF output; `sigc.py` rejects the program at `pragmas`.
- Machine (M6, D16): the pragma `Machine "mps2-an385"` selects the QEMU `mps2-an385` target and an ELF32 output.
- Clocks (M9, D19): stage 2 keeps clock formulas as binary decision diagrams; `sigc.py` never did, so the m9 cases are stage-2 only. Diagram steps share one budget per program, sized from its definitions, obligations and `when` conditions; a program that exceeds it is a capacity error (`F_CAP_BDD`). The clock pass's step bound reaches `PARSE_CAP` at about a 3600-deep `when` chain or a 2600-wide `default` chain under an obligation. A cycle with exclusive edge clocks is split on at most `SPLIT_CAP` conditions.
- Affine roots (M9c): the hidden clock `clk_i'k` of `affine_clock_relation` is a presence column of the `.in` file, placed after every root created before the intrinsic's expansion.
- Time: stage 2 compiles `compiler/sigc.sig` in about 88 s against about 5.1 s for `sigc.py`. `m3/input_far.sig` takes 13 s, and a 9000-equation body takes 39 s against 1.3 s. Programs needing more than 16 clock rounds pay a floor of about 2.3 s, and thousands of `on` guards cost quadratic time in `finish_model`.
