# Requirements and decisions

## R — Requirements (user, 2026-10-23)

> I'd like to implement the SIGNAL programming language (like Polychrony)

- **R1** The target is CPU machine instructions (mac mini native).
- **R2** Can be used for developing RTOS/device drivers and user-space programs like a dynamic linker (heavy OS primitive interfacing) without relying on external C.
- **R3** Can use whatever programming language (with fast-iteration, low dependencies).
- **R4** Eventually self-hosted.

## S — Specification

- **S1** Language reference: *SIGNAL V4 – INRIA version: Reference Manual (revised working version)*, Besnard, Gautier, Le Guernic, 2020-04-01, HAL [hal-02928452v1](https://hal.science/hal-02928452/document). Where this document extends the spec, the extension is named as such.

## D — Decisions (each approved by the user, 2026-10-23)

- **D1 Targets.** First target is macOS arm64 user space. Bare metal is AArch64 under QEMU `virt`, sharing the arm64 backend. Thumb-2 (Cortex-M) is required but deferred to a later phase.
  - Measured on this Mac: static Mach-O executables are killed at launch (exit 137) even when ad-hoc signed; dyld-loaded executables issuing raw `svc #0x80` syscalls run. Generated programs are therefore dyld-loaded and code-signed.
- **D2 Effects.** Load/store at an address, syscall, and raw instruction are built-in `external` models of class `unsafe` (S1 XI–1), each naming a resource. Order between effects is stated with `-->` (S1 XI–6.2). The compiler rejects two effects on the same resource with no order between them (extension). No inline imperative escape hatch. Interrupts are input signals.
- **D3 Automata.** `automaton` models stay deterministic (S1 XI–1.6) and never call unsafe effects. A driver is a `process` shell around a pure automaton: the shell reads via unsafe procedures, feeds values to the automaton, and performs writes ordered by `-->`. Hand-written state variables with guarded processes inside a `process` remain allowed.
- **D4 Integer types.** `short`/`integer`/`long` are 16/32/64 bits on every target; overflow wraps. Extension: unsigned `ubyte`/`ushort`/`uinteger`/`ulong` (8/16/32/64); bitwise `and`/`or`/`xor`/`not` and shifts on unsigned types only; value-preserving widening implicit, same-width signed↔unsigned explicit. `pointer` (S1 V–2) is the only target-width type, with ± offset, compare, and explicit conversion to/from `ulong`/`uinteger`.
  - Approved 2026-10-25, M6: `pointer` is 8 bytes on arm64 and 4 bytes on Cortex-M (D16).
- **D5 Self-hosting.** Table-driven (APL style), no recursion: column tables for syntax trees, table-driven parsing with explicit stacks, bounded `iterate` for fixpoints, built on S1 chapter IX. No recursive functions, tagged unions, or arenas.
- **D6 Memory.** Array capacities are declared constants. On macOS user space, large arrays live in fixed windows carved at compile time from one address-space reservation made at startup, each followed by an inaccessible guard gap; arrays never move. Measured: 16 KiB pages; one 2^46-byte reservation succeeds, 2^47 fails; pages cost memory only when written.
  - Approved 2026-10-24, macOS user space only: every non-constant array gets a window regardless of size; constant tables stay in `__DATA`. Windows are rounded up to 16 KiB and each is followed by a 16 KiB guard gap of no-access pages inside the reservation, so no later mapping can fill it. The reservation is exactly the total, computed at compile time. If the reservation fails, the program exits with status 3 and `memory reservation failed` on stderr.
- **D7 Bootstrap.** Python 3.14, standard library only, written table-driven so passes port to SIGNAL by transliteration. It covers only the SIGNAL subset the self-hosted compiler is written in. It emits arm64 assembly and uses Apple `as`/`ld` until the compiler writes Mach-O itself (M3, D12).
- **D8 Clock structure.** A program's clocks may form a forest of clock trees rather than a single tree. Each root clock becomes a presence input to the step function, supplied by the caller (for example, an interrupt dispatcher knows which interrupt fired). Clocks that fit no tree are rejected. This is broader than endochrony (S1 III–8.2), which the spec defines but does not require.
  - Approved 2026-10-24: any clock that nothing defines is a root, except that of a signal defined only by a constant (`X := 5` with no `^=` and no reader that reaches it), which has no clock and is rejected (amended 2026-10-27, M9a: S1 VI–1.1 1-c, IV–2; test `many_roots` moves to the rejected cases). Top-level input signals are added in M2 (D11) and add roots of their own; free roots stay allowed, and requiring declared roots stays deferred.
  - Approved 2026-10-24: `(x when b) default (y when not b)` with `^x = ^y` has clock `^x ∧ ^b`, and with constant `x`, `y` has clock `^b` (`[b] ∨ [¬b] = ^b`), recognised when `not b` negates the same condition. Other partitions and every other equality between clock formulas are decided on the diagram (D19; amended 2026-10-27, M9a).
  - Approved 2026-10-25, M5: on QEMU `virt` every root clock must be the clock of a top-level input named by an `Interrupt` or `Boot` pragma (D15); free roots are rejected there, since nothing supplies their presence.
  - Approved 2026-10-24: causality cycles that S1 IV–3.3 accepts because their edge clocks are exclusive are rejected until that canonical form exists (test `exclusive_cycle`). Lifted 2026-10-27, M9b: accepted by D19's split copies; `exclusive_cycle` moves to the accepted cases.
- **D9 Division.** Approved 2026-10-24. Integer division truncates toward zero; `x / 0 = 0` and `x modulo 0 = x` on every target (stored in τ(E2) per S1 VI–8, so it wraps when x does not fit), with no trap; the most negative value divided by `-1` wraps to itself (D4). `modulo` returns the Euclidean remainder `0 ≤ r < |b|`, extending S1 VI–8, which requires a positive divisor. Rationale: bare-metal targets have no process to kill, and arm64 `sdiv` and Cortex-M `SDIV` (with division-by-zero trapping off) already return 0.
- **D10 M1 types and arrays.** Approved 2026-10-24.
  - Integer literals have the S1 type (smallest signed type containing the value, S1 V–1); there is no adoption by context, so unsigned values come from conversions `T(E)` or from `$` without `init`. Signed and unsigned operands combine by the least upper bound of the D4 lattice (`ubyte ⊑ short`, `ushort ⊑ integer`, `uinteger ⊑ long`); pairs with no upper bound are rejected.
  - Shifts are the keyword operators `shl`/`shr` on unsigned left operands; an amount of 64 or more, or negative, gives 0.
  - A scalar constant is defined by a constant expression (S1 VI–2.1): literals, conversions (wrapping as D4), constants declared earlier in the file, and the arithmetic, comparison and boolean operators, folded while parsing; the conditional and the composite operators (`^+`, `abs`, …) are not folded. A constant of enumeration type is not supported. A division or `modulo` by zero in a constant is rejected, although D9 gives 0 at run time. A constant that names itself, a later constant or a signal is rejected (S1 XI–2 permits declaration order). A delay's `$ init` and a declaration's `init` take a literal, an enumeration value, a constant name, or a parenthesised constant expression. Array constants are lists of those (amended 2026-10-26, M8). `$` on arrays, and lists as a delay's or an array declaration's `init`, came with M10b (D20).
  - An array index out of range at run time reads the element type's default value, and a write there defines nothing; no trap (as D9). A constant index out of range is rejected.
  - `iterate` bodies hold monochronous definitions only, except the reads of `$` that D20 allows (M10b); `X[?]` reads the previous iteration and arrays are updated in place, except where D11 copies them.
  - `if B then E1 else E2` (S1 VI–9) is in M1, for D5: it is the only value selection available inside `iterate`.
- **D11 M2 models and effects.** Approved 2026-10-24.
  - Built-in effects are predeclared `unsafe` external procedures with reserved names: `load{R, T}(A)`, `store{R, T}(A, V)`, `syscall{R}(N, A0, …, A5)` with exactly seven inputs, and `instruction{R, W}(X)`. The resource `R` is an external type (`type R = external;`, S1 V–2); two effects share a resource when they name the same type. `T` is an integer type or `pointer`; `W` is an integer literal or integer constant name below 2^32. The static parameters of a built-in effect are types, integer literals and constant names; those of user models follow D18 (amended 2026-10-26, M8).
  - `syscall` returns one `long`: `x0`, or `−x0` when the carry flag is set (−errno). `instruction` passes `X` (`ulong`) in `x0` and returns `x0`; the word may clobber `x0`–`x17` and the flags, must preserve `x19`–`x29`, `sp` and `x30`, and must not branch out.
  - Approved 2026-10-25, M6: on Cortex-M (D16), `W` is one 32-bit Thumb-2 instruction written in ARM ARM order, first halfword in the high 16 bits; the compiler swaps the halfwords into memory order. `X` is passed in `r0:r1` and the result returned there; the word may clobber `r0`–`r9` and the flags, must preserve `r10`–`r12`, `sp` and `lr`, and must not branch out.
  - The ordering check ignores clocks: two effects on one resource must be connected by a dependence path even when their clocks are exclusive. Load/load pairs are included. A `-->` endpoint naming a signal whose definition calls models covers those instances' equations too. An `iterate` runs as a unit: two effects in one body need a path inside the body, and an effect in a body is ordered with an effect outside it, or in another body, when the loop reaches the other's node, or is reached from it, in the step's dependence graph (amended 2026-10-25, M4).
  - Models, types and constants share one program-wide namespace, visible everywhere (S1 scopes them to their level); signals and labels are local to their model; a declaration that reuses a built-in name or a model name is rejected. A model that is never called is not type-checked. Model calls, `syscall` and `instruction` inside `iterate` are rejected, as are effects in its `with` part, except the calls of functions D20 allows (M10b); `load` and `store` in a body run once per iteration (amended 2026-10-25, M4). Both arms of `if` are computed, so an effect inside an arm of `if` is rejected (amended 2026-10-25, M4). Recursive calls are rejected; a call of a model with q outputs defines q signals, `(X1, …, Xq) := P(…)`, the targets taking the outputs positionally, and is accepted only as an unguarded equation of the model, not inside `on`, `case`, a state action or `iterate` (amended 2026-10-26, M8).
  - In a guarded process, a member whose clock nothing defines takes the clock of the innermost guard (S1 VII–6 `l1 = H1`); the tick of the process is the union of its members' ticks (S1 VII–5) and is checked equal to the guard's clock (D19; amended 2026-10-27, M9b). A model instance called inside a guarded process inherits the guard. Guards whose clocks depend on each other are rejected.
  - The fourth argument of `Automaton_Transition` is a priority (default 0): an integer literal, possibly negated, or a constant name; transitions from one state are tried in descending priority, ties in textual order (S1 XI–1.6). `Automaton_SetClock(E)` makes `when E` the automaton's clock in place of the union of its inputs' clocks; `Automaton_Clock()` denotes that clock; `Automaton_SetCurrentStateId(id)` is accepted and has no effect, since it names a variable of generated source that this compiler does not emit (amended 2026-10-26, M8). A labelled process `S :: P` inside an automaton is the state action of `S` and is the guarded process `on (when Automaton_IsIn(S)) :: P` (S1 XI–1.6); a label of an automaton that is not a state cannot label a process (amended 2026-10-26, M7). `Automaton_IsIn` has the automaton's clock. A guard on `Automaton_Transition` filters its trigger; `Automaton_Initial_State` cannot be guarded, and neither intrinsic statement can carry a label.
  - Arrays read through `X[?]` by their own gather, or in an iteration body cyclic only through such reads, are copied at the start of each iteration (S1 IX–13 accepts both). `with` initializes an array only from an array constant or an array signal of the same type.
  - A top-level input signal is a scalar, and its clock must be a root of its own; each step's stdin line carries the present inputs' decimal values after the presence characters. A program whose top model has no outputs writes no step line.
- **D12 M3 backend.** Approved 2026-10-24.
  - The compiler encodes arm64 instructions from an instruction-row table (one row per instruction, operands in columns) and resolves branches and `adrp`/page-offset references in one pass after data is laid out; a field that does not fit is a compile error, with no branch relaxation. The runtime's error exits sit before the step loop and root presence is read through a register index, so neither program size nor root count meets a field limit; only one iteration body over 1 MiB of code would.
  - The executable is a dyld-loaded Mach-O with seven load commands: `__PAGEZERO`, `__TEXT`, `__DATA`, `__LINKEDIT`, LC_LOAD_DYLINKER, LC_MAIN and LC_CODE_SIGNATURE; header flags DYLDLINK|PIE; no section headers; `__TEXT` and `__DATA` file sizes rounded to 16 KiB; the `__LINKEDIT` file size is the signature length. The output is written to a new file renamed over the target, so recompiling over a running executable leaves the new one launchable. Data holds no absolute addresses, so no rebase information is needed.
  - The signature is an ad-hoc CodeDirectory (version 0x20100, flag CS_ADHOC, SHA-256 over 16 KiB pages, empty identifier). `codesign --verify --strict` must accept every executable.
  - Apple `as`, `ld` and `codesign` serve only as test oracles in `tests/backend.py`, retired with the bootstrap at M4; the test suite runs the compiler with an empty PATH.
- **D13 M4 self-hosting.** Approved 2026-10-25.
  - The SIGNAL compiler runs one step per compilation; each pass is an `iterate` over column tables (D5). Language extensions it needs are added to `sigc.py` first and kept only where the compiler cannot be written without them.
  - The compiler keeps the `sigc SOURCE -o OUTPUT` command line: the runtime keeps argc and argv, and source and executable move through `syscall` effects.
  - Extension: a string literal may initialize a `constant` array of `ubyte`: one literal `"…"` without line breaks, in which the escapes of S1 II–1.2 are decoded, whose decoded bytes must number exactly the array size (amended 2026-10-26, M7).
  - Extension: `X := 0 .. E` defines the index of an `iterate` with a count chosen at run time: start 0, step 1, `clamp(E + 1, 0, N)` iterations for `[N] integer X`, computed on 64 bits with a signed `E` sign-extended and an unsigned one zero-extended, so every negative `E` gives none and `E + 1` cannot wrap. The capacity, not the type of `E`, bounds the count (S1 IX–6 defines `E1 .. E2 step E3`; this is its start-0, step-1 subset). From M10b a constant start `a .. E` is accepted the same way. `X` can only be the index of `iterate`.
  - The runtime keeps argc in `x25` and argv in `x26`, set before the first runtime instruction, so an `instruction` effect can read them (D11 preserves `x19`–`x29`).
  - Each pass is checked against a dump of the same pass from `sigc.py`; the exit check is executables byte-identical to `sigc.py`'s on every case, the full suite passing with stage 2, and stage 2 byte-identical to stage 1.
  - `sigc.py` stays in the repository as the frozen stage 0 and is not extended after M4; `tests/backend.py` and its `as`/`ld` oracles are retired.
- **D14 M5 output format.** Approved 2026-10-25: bare-metal programs for QEMU `virt` are written as ELF executables, loaded with `qemu-system-aarch64 -M virt -kernel`.
- **D15 M5 bare-metal programs.** Approved 2026-10-25.
  - Extension of S1 XI–7: a top model's `pragmas … end pragmas` may hold `Interrupt {X} "N"`, making input `X` present in the step that handles GIC interrupt `N` (16–31, each used once), and `Boot {X}`, making `X` present in one step run before any interrupt. Such inputs are `event`, each on a root clock of its own; on `virt` every top-level input is named by exactly one of them, and a program with `Interrupt` pragmas needs a `Boot` pragma, since only a step can enable the GIC. A top model with either pragma is compiled for QEMU `virt`; one without stays macOS, and `sigc SOURCE -o OUTPUT` is unchanged. `syscall` is rejected on `virt`.
  - The `virt` runtime sets SP to a 16-byte-aligned stack, fills the array window slots, runs the boot step, then loops: `wfi`; read GICC_IAR; an id with no pragma runs no step; otherwise its root is present and the others absent, the step runs, and its line is written byte by byte to the PL011 data register in the macOS step-line format; then GICC_EOIR completes every acknowledged id below 1020, so an unmapped interrupt cannot block later ones. The id is matched by a chain of compares, one per pragma. The runtime does not program the GIC or the timer; the program does, with `store` and `instruction` effects (D3). There is no exception vector table and no runtime termination; a program may power off with PSCI SYSTEM_OFF through `instruction` (`hvc #0`).
  - The executable is an ELF64 image with one RWX PT_LOAD from file offset 0 at 0x40000000 and no section headers; arrays and the stack lie in its zero-filled tail (p_memsz > p_filesz), and QEMU rejects an image larger than RAM. The output-buffer word stores in the `true`/`false` printer become byte stores, since unaligned accesses fault with the MMU off; macOS executables stay byte-identical to `sigc.py`'s.
  - Measured on QEMU 11.1.2: entry at EL1 with the MMU off and SP = 0; an unaligned `str` faults; `wfi` with interrupts masked wakes on the virtual timer, GICC_IAR = 27; PSCI SYSTEM_OFF via `hvc` exits QEMU with status 0; unpolled PL011 writes arrive complete (QEMU only: real hardware needs TXFF polling).
- **D16 M6 Cortex-M programs.** Approved 2026-10-25.
  - Extension of S1 XI–7: a top-model pragma `Machine "mps2-an385"` compiles the program for QEMU `mps2-an385` (Cortex-M3); any other machine name is rejected. Bare-metal pragmas without it keep meaning `virt` (D15). The target is one value (macOS, `virt`, `mps2-an385`). The D15 rules on `Interrupt`, `Boot`, inputs and roots hold, with `Interrupt {X} "N"` naming exception number `N`: 15 (SysTick) or 16–47 (IRQ 0–31), each used once. `syscall` is rejected.
  - The runtime sets PRIMASK, enables the UART0 transmitter (CTRL = 1, BAUDDIV 16; the runtime is the UART's only writer, and a byte written before TXEN is lost), runs the boot step, then loops: `wfi`; read ICSR.VECTPENDING as `N`; `N` below 15 runs nothing; an `N` with no pragma runs no step and is cleared; otherwise its root is present and the others absent, the step runs and its line is written byte by byte to the UART0 data register; then the runtime clears `N` (15: ICSR.PENDSTCLR; 16–47: NVIC_ICPR0), after the step so the step can clear its device first. An enabled level-sensitive interrupt that no step clears stays pending and the loop spins. The program programs SysTick, the NVIC and devices (D3), as on `virt`.
  - Code: every instruction is a 32-bit Thumb-2 encoding, so the code table keeps the 4-byte stride; 16-bit-only instructions are padded with `nop`, and there are no IT blocks. Branches use the T4 encoding with the image capped at 4 MiB; a conditional branch is a `b<!c>` over a following `b.w`. Addresses are built with `movw`/`movt`; data still holds no absolute addresses. Every value is held in a register pair; division and modulo use one 64-bit runtime routine that keeps the D9 results.
  - The executable is an ELF32 image (e_machine 40, the D14 format) whose ELF and program headers are not loaded and whose one PT_LOAD sits at address 0 from file offset 84. It starts with the vector table: the stack top in the zero-filled tail, then the entry address with the Thumb bit. Arrays and the stack lie in the tail. The compiler rejects an image whose memory size exceeds 4 MiB, since QEMU would wrap it into the RAM mirror without an error. Signal and delay slots stay 8-byte aligned, since an unaligned `ldrd`/`strd` faults.
  - Tests run under `qemu-system-arm -M mps2-an385 -cpu cortex-m3 -nographic -no-reboot`; `-no-reboot` stops a program that resets the board from looping without bound. `tests/differential.py` checks that seeded random programs over the D4 integer types (`pointer` excluded: its width differs by design) print the same trace on Cortex-M as on macOS; failing seeds are kept in `tests/differential_seeds.txt` and frozen as cases.
  - Measured on QEMU 11.1.2: reset reads MSP and PC from words 0 and 1 at address 0 and ignores the ELF entry; RAM is 4 MiB at 0, mirrored at 0x400000; with PRIMASK set, `wfi` wakes on a pending SysTick or IRQ; SDIV/UDIV by 0 give 0; a fault with no handler ends QEMU with a lockup (status −6); a board reset without `-no-reboot` loops to 1.2 GB of memory.
- **D17 M7 rewrites.** Approved 2026-10-26.
  - Scope: an inner `where` adds its declarations to the enclosing model, and a name already declared in that model is rejected (S1 would shadow it). Hiding `P / X` checks that `X` is a local signal of the model and has no further effect; an interface signal or an undeclared name is rejected (S1 ignores an undeclared name). `array I to N of P end` declares `I` in the enclosing model, and a signal already named `I` there is rejected (S1 hides `I`). A type alias `type A = µ;` must precede its first use in source order. A model cannot be declared in an inner `where`, since each model's rows form one contiguous range (amended 2026-10-26, during M7).
  - Classes: `node` and `function` declare at least one output; a `function` contains no `$` (nor `cell`, `var`, `after`, `from`, `count`), calls only functions, and all its interface signals are synchronous. A top-level `function` with several inputs is accepted when its clock equations make them one root (amended 2026-10-26, during M7). Endochrony is not checked (D8).
  - Rewrites: `cell`, `var`, `after`, `from`, `count` and `|*` are accepted only as the whole right-hand side of a definition `X := …`; inside a larger expression they are rejected. `cell`, `var`, `after`, `from` and `count` are also rejected inside a guard, a `case` branch, a label or a state action (amended 2026-10-26, during M7). `var E` is accepted where every operator of the definition it occurs in is monochronous, so its context clock (S1 IV–2) is the clock of the defined signal; any other occurrence is rejected, and a definition holds at most one `var` (amended 2026-10-26, during M7). The operand of `var` is a signal name, since the compiler creates its memory signal with that signal's declared type (amended 2026-10-26, during M7). The modulus of `count`, the size of `E |* N` and the bound of `array I to N` are an integer literal or a constant name, and the modulus is positive (amended 2026-10-26, during M7). The size of `E |* N` must equal the size of the array it defines (S1 IX–5), and the range of `array I to N` or `indices(N)` must fit the arrays it defines; a user range `0 .. B` is not checked, and an out-of-range element is not stored (amended 2026-10-26, during M7). `case` defines distinct signals per branch; one signal across branches is a partial definition `X ::= E` per branch (D19; amended 2026-10-27, M9c). `case` values are literals, enumeration values or constant names; a duplicate value through a constant declared later in the file is not detected (amended 2026-10-26, M8). `abs` is defined on the signed integer types, since S1 XIII–4 names `integer` and it is the identity on the unsigned ones (amended 2026-10-26, during M7); `left_tt` is defined on booleans. The operands of `after`, `from` and `count` are events, as in S1 VI–4.5 (amended 2026-10-26, during M7). In `T[E] \\ V`, `V` must be synchronous with `E` (S1 IX–7.2: ω(V) = ω(T)); the rewrite copies `V` four times, so nested recoveries grow as 4 to the depth, as nested `abs` and `^-` grow as 2 (amended 2026-10-26, during M7). Because the rewrite places `V` in the arms of an `if`, an effect in `V` is rejected; a constant index `E` is rejected because a constant has no clock (D8), and `\\` inside an `iterate` or `array` body is rejected because the rewrite uses `when` (D10) (amended 2026-10-26, during M7). `==` and `<<=` are accepted on scalar operands, where they are `=` and `<=`. `H1 after H2` and `E cell B` relate the clocks of both operands, so they are rejected when the operands are separate roots (D8) (amended 2026-10-26, during M7).
  - Extension: a declaration `init` on a signal that is not defined by `$`, `cell` or `var` is rejected; S1 ignores it. When the definition also gives an `init`, the definition's wins (S1 VI–3.1) (amended 2026-10-26, during M7).
  - Pragmas are accepted on every model, and a pragma with a name other than `Interrupt`, `Boot` or `Machine` has no effect (S1 XI–7); those three stay on the top model only (D15, D16). A misspelled `Interrupt` therefore leaves a macOS program.
  - Lexer: source files are UTF-8; the Latin-1 letters S1 II–1 allows in names are their two-byte UTF-8 encodings (`×` and `÷` are not letters). Strings decode every escape of S1 II–1.2 and reject any other; `\%` is also an escape in comments. The reserved words grow by `cell var after from count case in array to` and the intrinsic names `abs left_tt`; keywords fold case, so test cases naming signals `COUNT` or `IN` were renamed.
- **D18 M8 models, parameters and modules.** Approved 2026-10-26.
  - Parameters: a model declares formal static parameters `{ … }` before its interface: constant values (`integer N;`), types (`type T;`) and models (`process T Q;`, with `type process T = ( … );` naming an interface). An actual parameter is one token: an integer literal, a constant name, a type name, a model name, or a formal of the calling model; an expression actual goes through a named constant. A value is checked as a subtype of the formal's type, a model by interface equality and class. A formal value is a per-instance constant, a formal type is resolved per instance in signal declarations and effect parameters, and a formal model is resolved at the call; recursion through a formal model is rejected as a call of a model by itself. The command-line model has no formals.
  - Parameter restrictions: formals are visible in their own model only, since binding is per instance (S1 XI–2 extends them to embedded models); a formal cannot mask a program-wide type, model or constant name; a formal type cannot be an array's type or element type, nor the target of a conversion; a model with formals cannot be an actual model; a formal is not a constant where the parser needs a value (constant definitions, `$ init`, sizes, bounds, `case` values, priorities); a signal of formal type takes no `$ init` or declaration `init`, since the initial value is type-checked before binding.
  - Labels and classes: a label's clock `^L` is the union of the clocks of the signals defined under L and, for calls and effects under L, of the clocks of their arguments (S1 VII–5); a label with no member has no clock and is rejected. The clock of an automaton state S is `when Automaton_IsIn(S)`. `on L :: P` guards P by that clock. The tick copies the arguments of the calls and effects under L, so a call inside such an argument is instantiated again: an effect or an action there is rejected, and so is an argument that is a constant name or a constant expression, since a constant has no clock (D8). Reading `^L` or a `ref` signal inside an `on` body is rejected as a clock cycle. An `action` is a process whose calls must occur under a label (S1 XI–1.2). A model may declare `safe`, `deterministic` or `unsafe` after its interface, in accordance with its class; a safe model holds no memory and calls only safe models (S1 XI–6); safe and deterministic models contain no effects; a deterministic model calling an unsafe model is rejected, extending S1's rule for external callees to described ones. Without an attribute a process is unsafe (S1 XI–1.1: unsafe unless proved otherwise, and this compiler does not prove it), so a node or automaton calling a process with no attribute is rejected, and such a helper must declare `safe` or `deterministic`. `spec` on a model with a body is composed with the body (D19); on an external model it is still not parsed (amended 2026-10-27, M9b).
  - `ref X;` lets a model read the signal X of the nearest enclosing model that declares it (S1 XI–4, policy 2); defining X there is rejected, and `ref` declarations precede embedded models, so each model's slots form one range.
  - `E ** N` is accepted on integer `E` with a constant integer exponent `N ≥ 1`, a literal or an earlier constant name, and is `E * … * E`; a signal exponent and `N ≤ 0` are rejected. The rewrite copies `E` N times, so a call in `E` is instantiated N times and an effect in `E` is rejected. Both operands of `**` bind tighter than it (S1 C–VI.3, `E19 ::= E20 ** E20`), so `A ** B ** C` must be parenthesised.
  - Modules: `module M = … end;` groups declarations in the compiled source file. Names stay program-wide (D11), so one name declared in two modules is rejected; S1 XII–1 resolves such names by `use` order, and that lift is left for later. A `private` declaration is visible only inside its module; any other module declaration is visible in a model or module that names the module in `use` (non-transitive) and everywhere inside its own module. Visibility is a parse-time name check, like the type-name check in declarations, and applies to every model, called or not. Virtual (bodiless) objects and overriding are not supported.
  - Encodings, chosen by test-surface comparison: formals and `ref` slots live in their own parameter table, not as signal rows; a call's extra outputs are a sub-state of the call reduction; visibility is one sweep over the tokens, not a check at each resolver; formal types join the local-name stack.
- **D19 M9 clock algebra.** Approved 2026-10-27.
  - Canonical form: Clock formulas are reduced ordered binary decision diagrams over the root clocks and the boolean conditions of `when` (S1 IV–1 encodes the same algebra as polynomials over Z/3Z; the diagram is the canonical form of the equivalent boolean algebra), built inside the clock pass as its APPLY and CHECKS states. Two clocks are equal when their diagrams are one node; a clock tree is still emitted, and a clock is placed in it by five rules (sample of its parent; union of two siblings; constant union `[b] ∨ [¬b] = ^b`; `^b` from a condition; `min_clock` solution), each checked on the diagram instead of on syntax. Chosen by test-surface comparison over Z/3Z polynomials (docs/decisions.md 2026-10-27).
  - Relations `^<`, `^>`, `^#` are checks: each pair of distinct members is proved on the diagram or rejected; a relation never fixes a clock that nothing else defines, which is `min_clock`'s job (S1 XIII–1). `^0` is the empty clock: a signal whose clock is empty is emitted nowhere, and its slot keeps the value no step writes. A signal whose only clock definition is `^= ^0` is rejected as undefined, and a relation on an input root is rejected as "cannot be shown" (M9b). A `when` condition enters the diagram after chasing `not`, copies and `when`, with one level of `and`, `or` and `xor` below the chase; `=` and `/=` on booleans and deeper formulas are opaque variables (M9b). Checks are pairwise, so a chain of n members costs n² diagram jobs: a 120-member `^#` chain takes about 10 minutes (M9b).
  - `assert`: `assert (| CONSTRAINT |)` and `assert(B)` narrow a care set under which every check is made; they never merge clocks. `assert (| E1 :=: E2 |)` assumes the clock equality and leaves the value equality unchecked. An assertion on a boolean that no clock formula shares discharges nothing. A contradictory set of assertions is accepted and discharges every check (M9b).
  - Causality cycles whose edge clocks have an empty product (S1 IV–3.3) are accepted: the cycle's rows are emitted once per assignment of at most `SPLIT_CAP` = 4 splitting conditions, each the presence of a condition defined outside and upstream of the cycle, under a branch chain that shares the registers; more splits reject with `needs more than 4 splits`, and a cycle separable only by a condition defined inside or downstream of it rejects with `cannot be split by a signal it defines`. Such inside splits count toward `SPLIT_CAP`, so a cycle can report the first message where the second applies; a cycle no assignment opens keeps `causality cycle` (M9b). Narrowings (M9b): root presence is never split (treated as either value); a cycle through an `iterate` body, or whose core exceeds `CORE_CAP` = 256 rows (about 125 links of a chain cycle) or 1024 edges, keeps `causality cycle`; the variable is picked by a walk of at most 64 steps and edge liveness by a search of at most 256 steps, an edge beyond either counting as live; the `schedule` dump prints the unsplit order.
  - `{a --> b} when C` is accepted only with the braces and the `when` together (S1 XI–6.2), with one signal on each side of `-->` (`{ } when takes one signal on each side of -->`); for cycle splitting its edge holds at `[C]`, and at every instant when `C` is an event or not boolean, which over-approximates `^a ∧ ^b ∧ [C]`. The effect-ordering check ignores clocks (D10), so effects are ordered as by `a --> b` (M9b).
  - `spec` on a model with a body is composed with the body (S1 XI–6); `spec` on an external model is still not parsed (D18).
  - `X :=: E` with X otherwise undefined is `X := E | X ^= E`, which orients the equation from E to X where S1 VI–6 does not, with the type rule of `:=`; only the left side is defined this way. Inside a guard H it defines X as `E when H`, when X is a single signal name. With both sides defined it is accepted only when their clocks are equal under the care set, and the value equality is assumed (M9b).
  - `min_clock(X)` solves `ω(X) = Q ∗ ω(X) + R` as `R` (S1 XIII–1), checks that `R` is a solution, and rejects `R = 0`; on a clock with no freedom it is a no-op. Only a direct self operand is solved (`X := A default X`, `A ^> X`); a class with two different solving relations is rejected with `min_clock of X has more than one clock relation` rather than joined (M9b).
  - The tick of a guarded process is the union of its members' ticks (S1 VII–5): `^X` for `X := E`, `^E` for `X ::= E`, the model's tick for a call, the argument's clock for an output-free call or an effect. It is checked equal to the guard's clock under the care set; state actions are guards (M9b). A nested guard ticks only at its own condition, so a guard whose only member is a nested guard is rejected (S1 VII–6). `case` branches and `{ } when` dependences are not tick-checked, and `assert(B)` inside a guard does not count toward its tick (M9b).
  - `affine_sample`, `affine_clock_relation` and `affine_unsample` (S1 XIII–2) are expanded at the end of parsing with hidden signals, like `count`, `cell` and `var`; the hidden clock `clk_i` of `affine_clock_relation` is a hidden input, so it is a root with a presence column in the input file (its column follows root creation order), and it is rejected on `virt` (D15). The relation is a statement with no target. They are accepted only in the top-level process (`can only be used in the top-level process`). Their parameters are an integer literal, a negated literal or a named integer constant, as for the modulus of `count`; operands are signal names. The operands x, y of `affine_clock_relation` must be signals whose clocks nothing else defines; `phi` of `affine_sample` is a non-negative integer and may exceed the period, that of `affine_clock_relation` any integer (M9c).
  - Partial definitions `X ::= E` (S1 V–10, VI–1.1 1-c) are accepted on any local signal, `shared` or not, and rejected on a top-level output (`output X cannot have partial definitions`; outputs of instantiated models are not checked). The chain is left-nested, `((E1 default E2) … ) default En`, then `default (En+1 when …)` with `defaultvalue`; without it the signal keeps its previous value at instants of `^X` no definition covers, through a hidden `ZX := X $ init V` (one register per signal), where V is the `shared … init V` value or else the type's default (0, false; an event is present). A signal no definition reaches is rejected as `partial definitions of X need a clock`, with the suggestion `min_clock(X)`. Pairs of partial definitions are checked exclusive under the care set, and arms of one `case` statement are exclusive by construction, a guard counting as its nearest enclosing case branch; exclusivity that needs value reasoning is not proved, so definitions under two separate `case` statements over one value, and S1 VII–7's statevar statechart (`partial definitions of Q1_State may coincide`), are rejected. A duplicate case value through a constant declared later (D17) makes the first branch's partial definition win silently. A constant `E` is rejected; mixing `:=` and `::=` is rejected; a definition not inside `^X` is reported as `partial definition … cannot be shown inside the clock of X`. Tuple partial definitions `(X1, …, Xn) ::= E` (1-e) came with M10c (D20); one whose right side is a call is still rejected.
  - `statevar T X init V;` is defined by `X ::= Ei` and read as `X?` (S1 V–11, VI–1.1 1-d, VI–2.3). The clock of X is the union of the clocks of its `Ei`, with no hold arm; a hidden `ZX := X $ init V` holds the value, and `X?` reads ZX's register at the clock of its context, so it is the value defined strictly before the current instant. The step-wide pair `NEXT_X … | ZX := NEXT_X $` of the design is not built: nothing ticks every step outside the clock tree (M9c). V is a literal, an enumeration value or a named constant. `X ::= defaultvalue E` on a statevar is rejected (`state variable X has no defaultvalue`, 1-d lists no such form); a statevar with no `::=` is `never defined`; `X?` with no context clock is rejected at the clock pass (`X? needs a context clock`); `X?` on another signal is rejected (`X is not a state variable`). Statevars on `virt`, inside a `case` branch or an `iterate`, and of event type are untested (M9c).
  - Encodings, chosen by test-surface comparison (docs/decisions.md 2026-10-27): diagrams as node columns inside the clock pass, not a separate pass; affine intrinsics as parse-end rewrites, not model instances.
- **D20 M10 arrays and tuples.** Approved 2026-10-27.
  - Arrays are flat row-major blocks typed by a nested chain `[n1]([n2]ν)`; `[n1, n2]ν` and `[n1][n2]ν` are one type (S1 V–4); strides are derived along the chain. Rank is at most 4, and every dimension is a constant expression (D6). `M[i, j]` is one element access with one bounds check per dimension (D10's out-of-range rule); a sub-array `M[i]` is a value, never a target, and an array outside a loop has one definition (S1 IX–4 permits several; multi-equation arrays use `::=`).
  - Construction (`[E1, …, En]`, `|+`, `E1 .. E2 step E3` with `E1` and `E3` constant, element definitions, restructuration) lowers to nested element-store rows inside the array's one definition.
  - Arrays cross model and top-level interfaces by copy. A step line carries an array as its elements in row-major order separated by spaces, and a single `-` when the array is absent, since every element has the array's clock (S1 IX–4). Inputs read the same format.
  - `==` on arrays is whole-value; `<<=` on arrays is rejected (S1 VI–7.2). Operators on arrays extend element-wise with scalar broadcast (S1 X–1).
  - A dependence endpoint `{X[i] --> Y}` orders the whole signal `X`, so two effects S1 leaves unordered, on different elements of one array, are ordered here and D2's unordered-pair check accepts more programs than S1 does.
  - `$` on arrays delays the whole block. `window` is S1 VI–3.3's definition. `X $ N` with a signal `N` is rejected: S1 bounds the window by `N`'s upper bound, which D4's types do not give.
  - Nested `iterate` is one loop over the product of its ranges, with derived indices (S1 IX–13). `with V := E` at any level is hoisted to index −1 of the product (S1's rewriting), so `V[?]` at an inner restart reads the previous flattened step. A run-time count (D13) is allowed only on the outermost range, so S1's incomplete iterations are rejected. A body may read `$` of a signal free in the loop; `when`, `default` and clock expressions stay outside bodies. A model called inside a body is expanded into the loop and must hold no `$`, `iterate`, effect or state (S1's `FILTER` cascade is rejected). `tr` takes rank 2; `*.` takes rank 1 and rank 2 operands.
  - Tuples are split before parsing, by a rewrite of the token stream, into one hidden signal per field named `X.A` (a name no user signal can have); the parser and lowering never see a tuple (amended 2026-10-28, M10c). A `struct` is a `^=` group of its fields; a `bundle`'s fields keep their own clocks. A tuple-typed expression is a name, a tuple value, a call result or an element of an array of structs; others are rejected. Nesting depth is at most 4; an array of structs is a struct of arrays; an array of bundles is rejected (S1 V–5). `==` on a struct is whole-value into a scalar target and field by field into a tuple target, `<<=` on a struct is rejected; both are pointwise on bundles. Tuple partial definitions `(X1, …, Xn) ::= E` split per component and follow D19.
  - Effects keep D11's types: a driver's register block is a `struct` value whose fields the program loads and stores with scalar `load`/`store` at offsets it writes.
  - Encodings, chosen by test-surface comparison (docs/decisions.md 2026-10-27): the stride derived, not stored; one product loop, not a loop stack; construction as nested stores in one definition, not a chain of hidden signals; tuples split before lowering, not tuple-typed rows.
  - Landed 2026-10-28, M10a1: shapes of rank at most 4 in both spellings, also through type aliases; multi-index access; nested constant lists; sub-array values; `dim`, `size` and `bounds`; element endpoints; array outputs of the top model. Narrowings:
    - A dimension, and the axis of `size`, is a literal or a constant name; `[K + 1]` and `size(M, 1 + 1)` are rejected. `size(T)` means `size(T, 1)`; the axis counts from 1. `dim` and `size` are constants, as S1 IX–1 says.
    - An array type of rank 2 or more has fewer than 2^31 elements.
    - `dim`, `size` and `bounds` are intrinsics unless the file declares a model of that name anywhere, in which case every call of that name is the user's model.
    - An element endpoint stands alone after `|` or `(|`, or next to `-->`. Inside `{ … }`, as a range `X[i .. j]`, or on a label it is rejected. Since it orders the whole signal, `X[0] --> X[1]` is a causality cycle, a program S1 accepts.
    - Messages print a multidimensional array type with one size only.
  - Landed 2026-10-28, M10a2: array inputs, array formals and array outputs of submodels; an array signal defined by an array signal of its type (`B := A`); chained access `M[i][j]`, the same access as `M[i, j]` (S1 IX–7.1); recovery on a multi-index access (S1 IX–7.2); enumerations with expressions; ranges and `step` inside brackets; restructuration `I : E` and element definitions `X[I] := E` (S1 IX–9, IX–11), where an element no definition reaches reads its type's default value, one of the values S1 allows; `|+`; whole-value `==`; extraction (S1 IX–8). `m1/restructure_alone`, `m2/input_array`, `m2/submodel_array_input` and `m4/lower_array_definition` became accepted. Narrowings:
    - An enumeration, `|+`, restructuration or extraction is a value only as the whole right side of a definition; `(X |+ Y) |+ W`, `[I, J] == [J, I]` and `(M[I])[J]` are rejected.
    - A restructuration's value array has exactly the index array's size, and its value is a scalar per index; S1 also allows a larger value array and sub-array values.
    - A range inside brackets has constant bounds, and its elements are `integer`. A range without `step` starts at 0, as in D13, while `a .. b step c` may start anywhere; the two spellings agree from M10b on.
    - Extraction takes at most two index arrays, each of rank 1 and all of one size, and does not mix an index array with a scalar index.
    - An element definition `X[I] := E` stands directly after `|` or `(|`; a labelled one is rejected.
    - `step` is a contextual name, so a signal may still be named `step`.
    - An endpoint with more indices than its array's rank is rejected.
  - Landed 2026-10-28, M10a3: operators on arrays (S1 X–1), element by element with a scalar operand applied to every element, on arithmetic, comparison, boolean, shift, conversion, `abs` and `if`; `when` and `default` on whole arrays. `m1/array_operator` became accepted. An element-wise definition is one implicit loop over the target; array `when` reads its operand's storage, and array `default` copies the block of the present operand. A declared constant index table, a constant range or a `step` range whose values fall outside the array is rejected, like a constant scalar index (D10). Narrowings:
    - An operator on arrays is the whole definition of an array signal; `(A + 1)[0]`, `(A + 1) when C`, a partial definition `V ::= A + 1` and an element-wise definition inside `iterate` are rejected with `operator + on arrays must be the whole definition of an array signal`. Its array operands are signals or constant tables.
    - `when`, `default`, `$`, clock operators and ranges are rejected inside an element-wise definition, and so are `syscall` and `instruction`, as inside `iterate` (D11); `load` and `store` run once per element, ordered by D2 like any other effect.
    - An array `default` takes operands of one size and element type. `==` and `<<=` keep their whole-array meaning, and `bounds` is not extended.
  - Landed 2026-10-28, M10b: `$`, `$ N` and `window` on arrays, with `init` taking a constant name or a list (S1 VI–3.2–3.4), and a scalar `init` for `window 2` of a scalar (VI–3.3 2(d)); `init` lists on array declarations; nested `iterate` and `array` as one product loop, `<< >>` and multi-argument indices, `next` pairs, element and tuple targets in bodies; `$` in a body of a signal the loop does not define; ranges `a .. b` starting at any constant, so the two range spellings agree; sequential enumeration (S1 IX–15); calls of functions inside bodies; `tr` and `*.` (S1 IX–16), with S1's `byte_adder` and matrix product as cases (`m10/`). `m1/array_delay` and `m4/range_start` became accepted; `m1/iterate_nested` and `m2/call_iterate` keep their rejections with new messages. `tr` and `*.` lower to whole-array templates, not to the parse-time rewrite into loops the design named: the body is parsed before its `where` declarations, so ranks are not known at parse time. Narrowings:
    - The size of `$ N` and `window N` is a positive constant; `X $ N` with a signal `N` is rejected. A list `init` holds integer literals and their conversions, as array constants do, and sits directly after `init`; `$ N init (E)` with a parenthesised expression is rejected.
    - An inner `iterate` stands directly after `of`; the tuple index form `iterate (I, J) of` is rejected. A body's own signals take no `$`; `window` is rejected inside a body, though `$ N init Z` on a free signal is allowed. A signal has at most one `with` seed across all levels, and an array seed is an array constant or an array signal, not a scalar.
    - A model called inside a body is a `function` with no `iterate`; S1 also allows stateless processes. A call inside a `with` seed is rejected.
    - A plain range `a .. b` that reaches an output is rejected (`a range can only be the index of iterate`); a `step` range is a value. A constant range whose count differs from the declared size is clamped to the size, as D13's run-time count is.
    - A sequential enumeration's first part is a `{ }` iteration with `to`, its bounds are literals or constants, and it is rejected inside `iterate`, a guard, `case`, a label or a state. Its header names may repeat, and elements no part covers read 0.
    - `tr` takes rank 2 only; `*.` takes integer elements of one type (S1's µ1 ⊔ µ2 is not computed). Their operands are named array signals or constants, and the result is the whole definition of an array signal outside `iterate`, so `tr (tr M)` and chained `*.` go through a named intermediate; a dot product `V *. V` is a scalar and may stand inside an expression, but not inside a body. `tr` is a keyword.
  - Landed 2026-10-28, M10c: `struct` and `bundle` types, inline and through type aliases, nested to depth 4; field access chains `X.A.B`; tuple values `(E1, …, En)`, scalar broadcast into a tuple target, and calls with tuple outputs; `==` and `:=:` on tuples, `if`, `$`, `window`, `cell`, `when`, `default` and clock operators on structs, a struct's clock being its first field's; bundle `spec` relations (`^#`, `^<`); arrays of structs as structs of arrays, with `size` and `dim` taken from the first field; tuples as top-level and submodel inputs and outputs; tuple partial definitions (VI–1.1 1-e). The exit program, a UART driver with a `struct` register block and a `bundle` status with `spec (| TX_READY ^# RX_VALID |)`, runs on `virt` and `mps2-an385` (`m10/driver_struct_*`). A step line carries a tuple as its fields in declaration order, flattened, `-` for an absent field; an array of structs carries one field's elements after another, not one element's fields after another. Self-compile peaks at 189 MiB RSS (143 MiB before M10c): about 25 MiB is the copy of the token columns that the rewrite costs every compile, the rest the compiler's larger source. Narrowings:
    - A tuple cannot be a state variable or a constant, and a tuple signal has no declaration `init`; a tuple value cannot be a call's argument, and a call inside a tuple value or with tuple outputs is the whole definition.
    - A bundle cannot be a field of a struct or bundle, or an array element; a field of tuple type has no array prefix. A bundle without `spec` leaves its fields unrelated. A `spec` names only fields of its bundle.
    - `<<=` on structs, `==` between a struct and a bundle, and `==` on elements of an array of structs are rejected; `==` on whole arrays of structs is accepted. `M.A` on an array of structs is the whole array of field `A`.
    - `init` on a delay of a tuple is accepted only for `$ 1`; `$ N init` and `window N init` on a tuple are rejected.
    - A body defines fields, `M.A[I] := E` or `M[I].A := E`; a whole element `M[I] := (…)` is rejected.
    - A whole tuple is not an operand of `load`, `store`, `syscall` or `instruction`; a register block is accessed field by field (D11).
    - `tuple()` and `rtuple()` are not supported. Tuples in the interface of a model without a body carry no relations. Every field declaration, the last included, ends with `;`. A type alias names one type program-wide and is declared once; inside a type definition it is used after its declaration, while a signal declaration may use it earlier.
- **D21 M11 characters, strings and I/O.** Approved 2026-10-30.
  - `char` (S1 V–1.5) is a type of its own, 1 byte, holding a Latin-1 code 0–255; it compares by code, unsigned, and has no arithmetic and no implicit conversion. `'é'` in UTF-8 source is 233, as are `'\xE9'` and `'\351'`; a constant above 255, empty or holding two characters is rejected. `char(E)` from an integer or `boolean` keeps the low byte of `long(E)` (S1 3-f leaves other codes undefined); a char converts to the integer types as a `ubyte`. `boolean(C)` is rejected, as `boolean(ubyte)` is. A step line carries a char as its decimal code, input and output.
  - `string` (S1 V–1.6) is a flat value: a 256-byte block whose bytes 0..254 hold the content followed by zero bytes and whose byte 255 holds the length, so `maxStringLength` is 255. Content is UTF-8 bytes, not validated; a char is written as its UTF-8 encoding. With the zero tail, equality is block equality and S1's lexicographic order is the unsigned byte order of the blocks. Every producer (constants, `read`, the default `""`, `$ init`) writes that form.
  - A string constant decodes S1 II–1.2's codes and joins II–2.6's list form `"ab" "cd"`, whose parts may be separated by separators and comments; the annex grammar (XIV) omits the list form and Part A is followed. A raw tab, newline or form feed inside `"…"` and a decoded length above 255 are rejected. D13's `constant [N] ubyte` literal is unchanged.
  - A string is accepted in `$`, `when`, `default`, `if`, `cell`, `var`, partial definitions, constants, `case` through a named constant, and model interfaces. It is rejected as an array element, a tuple field, a `case` literal and an input or output of the top model, whose step line has no form for a string. No conversion leads to or from `string`; indexing, `size`, `|+` and operators other than comparisons are rejected.
  - A string built by `if` is accepted only as the whole definition of a signal or as one branch of another string `if`; at most one branch of a string `if` may itself be built by `if` or `default`, so `if … else if … else …` chains are accepted. Both restrictions keep two block results of one definition from sharing its storage.
  - `read`, `write` and `writeString` (S1 XIII–6) are effects on one predeclared resource, so D2 requires `-->` between any two of them; messages name the resource `string`. `write(M, X)` takes `X` of an integer type, `boolean`, `char`, `string`, `real` or `dreal` (reals amended 2026-11-02, M12a; `event`, `pointer`, enumerations, arrays and tuples are rejected) and writes M's bytes, X's text as a step line prints it (a char as UTF-8, a string as its bytes) and a newline; `writeString(M)` writes M and a newline. The newline keeps the shared stream line-structured. Writes precede the step's line.
  - `X := read(M)` writes M and reads one line from standard input after the step's presence line: an integer, boolean, `real` or `dreal` in the step-line input format (reals amended 2026-11-02, M12a: at most 1023 bytes), a char as exactly one UTF-8 character up to U+00FF, a string as at most 255 bytes. Any other line, or input ending without a newline, ends the program with status 2 and `read input malformed at step N`; end of input at a line boundary ends it with status 0. A string holding a newline can be written but not read back. `read` is rejected on QEMU `virt` and `mps2-an385` (`read is not available on …`); `write` and `writeString` go to the step-line UART.
  - Encoding, chosen by test-surface comparison (docs/decisions.md 2026-10-30): `string` is a kind of its own (`TK_STRING`) whose type row describes a `[256] ubyte` block, so delays, copies, `default`, `when` and `==` reuse the M10 array rows, over a scalar kind with its own copy, select and compare templates per ISA.

Where Python's `math` on macOS is itself more than 1 ulp from the true value (Apple's `tan`, up to 2.4 ulp), the bound is against the true value (user, 2026-11-03).
  - Phases: M12a reals, M12b complex numbers, M12c the XIII–4 functions, `arg`/`argd` (amended at M12b: `arg` is atan2, an XIII–4 routine) and the exit program; each phase gets its own cross-model review and commit, as D20's phases did.
  - Landed 2026-11-02, M12a:
    - Constants (S1 II–2.4): digits `.` digits with an optional exponent, or digits with an exponent; an exponent written with `d` or `D` makes a `dreal`, every other form a `real`. `1.` and `.5` are not real constants. The value is the nearest binary32 or binary64, ties to even, computed by the compiler; a constant that rounds to infinity is rejected (`real literal … does not fit in real`), one that rounds to zero is accepted. A leading `-` flips the sign bit, so `-0.0` exists.
    - `real ⊑ dreal` is the only implicit conversion; integers and reals do not mix, so `1 + 1.0` and `X := 1` with `X` real are rejected. `+ − * /` and unary `−`/`+` follow IEEE with round-to-nearest-even and no trap: division by zero and overflow give infinities and NaN (D9 rejects traps). `modulo` on reals is rejected; `E ** N` takes a real `E` and a constant integer `N ≥ 1` (D18). S1 VI–8.1 types the exponent as an integer, so a real exponent stays rejected and `pow` (M12c) is the real power (amended at M12c).
    - Comparisons are IEEE: a NaN operand makes `=`, `<`, `<=`, `>` and `>=` false and `/=` true; `==` and `<<=` on reals and arrays of reals compare the same way.
    - Conversions (S1 V–6.3): `real(E)` and `dreal(E)` accept integers, `boolean`, `char`, enumerations and reals; an unsigned operand converts by its value. Real to integer truncates toward zero to `long`, saturating at the `long` bounds with NaN giving 0 (the arm64 `FCVTZS` result, which S1 leaves to the implementation), then narrows as D4 does; `char(E)` is `char(long(E))`. `real(E)` from a `dreal` rounds to nearest, ties to even. `boolean(E)` from a real is rejected, as from every non-boolean type.
    - Step lines (U3): plain digits when the decimal exponent is in −4…15, otherwise `d.ddde±XX` with at least two exponent digits; `.0` on integral plain values; `nan` for every NaN, `inf`, `-inf`, `-0.0`. Input is an optional `-`, digits, an optional `.` and digits, an optional `e`/`E` with an optional sign and digits, or `nan`, `inf`, `-inf`, read to the nearest value, ties to even. Other text, `-nan` and a value that rounds to infinity are malformed (exit 2), as integer input above 2^64 is. `nan` reads as `0x7FC00000` and `0x7FF8000000000000`. A real input value holds at most 2048 bytes.
    - `write` takes reals and writes them as a step line prints them; `read` accepts a real target (D21 amended).
    - Targets (U1): on `mps2-an385` the first real token is rejected with `real is not available on mps2-an385` (or `dreal`). QEMU's `-kernel` entry runs with FP/SIMD trapped (measured 2026-11-02: an image storing `B`, executing `fmov d0, xzr` and storing `A` to the PL011 printed `B` only, the same image without the `fmov` printed `BA`), so every `virt` image sets `CPACR_EL1.FPEN = 0b11` before its first step, and its stack grows from 32 to 1024 bytes for the real printer's frame.
    - Narrowings: a real constant is a literal, a negated literal or a constant name; any other real expression in a constant definition is rejected. The compiler converts at most about 3350 real literals per program (`program exceeds compiler capacity: REALS`), and each literal costs about 40 ms of compile time, since the converter's iterate runs a fixed step budget per literal.
    - Encodings, chosen by test-surface comparison (docs/decisions.md 2026-11-02): constants converted at compile time over at program start; a fixed-capacity bignum, exact parsing with digits past the 768th folded into one sticky digit (fast_float's `max_digits`) and Steele–White/Dragon4 shortest printing, over Ryu with Eisel–Lemire; operands kept on the integer-register path with `FMOV` around each FP instruction, over FP loads and stores.
  - Landed 2026-11-02, M12b:
    - `complex` and `dcomplex` (S1 V–1.4) are pairs of `real` and `dreal`, default `0.0@0.0`. `E1 @ E2` takes two real operands and gives `complex`, or `dcomplex` when either operand is `dreal`; it sits at the `**` level and is non-associative (S1 Table C–VI.3), so `1.0 @ -1.0` negates the operand and `A @ B @ C` is rejected. `complex ⊑ dcomplex` is the only implicit conversion; reals and complex numbers do not mix, and `complex(E)` from a real is rejected (S1 V–6.3 3-e).
    - `+`, `−` and negation are componentwise. `*` and `/` follow CPython 3.14's `_Py_c_prod` and `_Py_c_quot` operation for operation, including their Annex G recovery of infinities, so a `dcomplex` result equals Python's `complex` bit for bit; the multiply-adds that this machine's CPython build fuses (every one in `_Py_c_quot`, the recalculation in `_Py_c_prod`) are fused here too. `complex` runs the same algorithm in binary32. `modulo` is rejected; `E ** N` is D18's repeated `*`, not Python's `c_powu`.
    - `=`, `/=` and `==` compare both components with IEEE equality; `<`, `<=`, `>`, `>=` and `<<=` are rejected. `real(E)` and `dreal(E)` from a complex give its real part, integer and `char` targets go through it, and `boolean(E)` is rejected.
    - XIII–5: `conj`, `rpart`, `ipart` and `modu`, with their `d` forms. `modu` is within 1 ulp of Python's `abs(complex)`, computed in binary64 with power-of-two scaling, `FSQRT` and one correction step, so no intermediate overflows or underflows spuriously.
    - A complex constant is `R1 @ R2`, each half a real constant form of M12a or a parenthesised negated literal (S1's `1.0 @ (-1.0)`); arrays of complex constants take such pairs as elements.
    - Step lines: a complex is its real part, a space and its imaginary part; an absent one is `- -`, one `-` per half, as D20's flattened tuples; an input line with one half present is malformed. An array of complex values carries all real parts, then all imaginary parts, as an array of structs carries one field after another (D20). `write` writes `re im` and `read` reads one line holding exactly two real numbers separated by one space, each one effect.
    - Arrays of complex values, delays (`$ N` included), `window`, `iterate`, `when`, `default`, `if`, `cell`, `var`, statevars, tuple fields and model interfaces follow the M12a rules. `mps2-an385` rejects the first `complex` or `dcomplex` token (`complex is not available on mps2-an385`); `virt` runs them.
    - Narrowings: a complex `init` needs parentheses, `$ init (A @ B)`, since `init` takes an E22 operand; a list or window init on a `dreal` or `dcomplex` delay must already have that type; `*.` on complex arrays is rejected, as on reals; the token text of the recovery operator is spelled `recover` in compiler messages, because the frozen bootstrap cannot hold a backslash in the message fragments.
    - Encoding (docs/decisions.md 2026-11-02 M12b): a pass after lowering rewrites each complex row into its real-part row in place and appends its imaginary-part row; an array of complex values becomes two arrays of reals. No row of complex type reaches clock calculus or the emitter, and a complex row the pass cannot expand is a compiler error. The pass checks the row capacity (`program exceeds compiler capacity: ROWS`).
    - M12a fixes found during M12b: a `real` literal or constant used as the init of a `dreal` delay, `cell`, `var`, statevar or `iterate` seed was stored unwidened; every init now widens at one place.
      Whole-array `==` compared real elements by their bits, so `[nan] == [nan]` was true and `[0.0] == [-0.0]` false; it now compares each pair with IEEE equality, as D22 states, for arrays of reals, of complex values and of structs with real fields.
  - Landed 2026-11-03, M12c:
    - The 22 XIII–4 names and `arg`/`argd` (XIII–5) are intrinsic functions over scalar operands, as `modu` is. Operands are `dreal`, a `real` operand widening; an integer or complex operand is rejected. `ldexp`'s second operand is `integer`, with D4's widening. `frexp` and `modf` are tuple-output calls, accepted only as the whole definition of a two-target tuple, `(Y1, Y2) := frexp(X)`; `frexp`'s exponent is `integer`. `arg(complex)` gives `real`, the binary64 atan2(im, re) rounded once; `argd(dcomplex)` gives `dreal`.
    - Accuracy (U4): `sqrt`, `fabs`, `floor`, `ceil`, `fmod`, `ldexp`, `frexp` and `modf` equal Python's `math` bit for bit; the others are within 1 ulp of Python's `math`, or of the true value where Python's result is more than 1 ulp from it. Special values follow C99 Annex F with no traps: where Python raises, a pole gives the signed infinity (`log(0)`, `log10(0)`, `pow(±0, y<0)`), overflow gives ±inf and any other domain error NaN.
    - Targets: macOS and `virt` run the same routines; `mps2-an385` rejects them with the real types (U1). The `virt` stack grows from 1024 to 1536 bytes for the deepest runtime frame chain, `sin` of a huge argument through the Payne–Hanek reduction (1424 bytes); generating the tables fails when a runtime, real-parse or number-print chain exceeds the stack. The row templates' own stack adjustments are outside that check; the deepest, `write` of a real, reaches 992 bytes.
    - Every program with a real token carries the routines: a minimal real program's image grows from 32901 to 49317 bytes.
    - Encoding (docs/decisions.md 2026-11-03 M12c): `sqrt`, `fabs`, `floor`, `ceil` and `modf`'s integral part are one instruction each (`FSQRT`, `FABS`, `FRINTM`, `FRINTP`, `FRINTZ`); the other functions are arm64 routines in the real runtime, ported from FreeBSD msun (commit 0e44056f19ab339fe7e37c03e49cf50b33bf1d6b) and, for `ldexp`, musl's `scalbn`, with `sinh`, `cosh`, `tanh`, `atan` and `atan2` finishing in double-double.
